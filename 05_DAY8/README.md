# Day 8. 뉴스 요약봇 만들기 — News Text Summarization

## 1. 프로젝트 개요

본 프로젝트에서는 뉴스 기사 데이터를 활용하여 추상적 요약(Abstractive Summarization)과 추출적 요약(Extractive Summarization)을 구현하고, 두 방식의 특징과 성능 차이를 비교하였다.

LSTM 기반 Seq2Seq 모델에 Attention Mechanism을 적용하여 뉴스 헤드라인을 생성하였으며, Summa를 이용한 추출적 요약도 함께 진행하였다.

초기 모델에서 발생한 UNK 반복 생성 문제를 해결하기 위해 이전 프로젝트에서 학습한 SentencePiece를 적용하였다. 추가로 ROUGE 정량 평가, Lead-1 기준 모델 비교, Attention Heatmap 시각화 및 실제 요약문의 문법과 핵심 정보 포함 여부를 분석하였다.

## 4. 프로젝트 수행 과정

### Step 1. 뉴스 데이터 수집 및 분석

뉴스 데이터를 다운로드한 뒤 데이터의 크기, 결측값, 중복 여부 및 문장 길이 분포를 확인하였다.

뉴스 본문과 헤드라인의 길이를 각각 분석하여 이후 전처리 및 모델 구성에 필요한 정보를 확보하였다.

### Step 2. 데이터 전처리 및 단어사전 구축

텍스트의 정규화, HTML 태그 제거, 소문자 변환, 축약어 처리 및 불용어 제거를 수행하였다.

뉴스에서는 날짜, 금액, 인원수, 비율 등의 정보가 중요하므로 숫자와 일부 단위 기호를 유지하였다. 또한 부정 표현이 제거되어 문장의 의미가 달라지는 것을 방지하기 위해 주요 부정 표현을 보존하였다.

본문에는 불용어 제거를 적용하였으며, 헤드라인에는 문장의 자연스러운 구성을 고려하여 불용어 제거를 적용하지 않았다.

학습 데이터의 토큰 길이 분포를 분석한 뒤 95백분위수를 기준으로 최대 시퀀스 길이를 설정하였다.

이후 단어사전 구축, Encoding, Padding 및 Tensor 변환을 수행하였다.

### Step 3. Attention 기반 Seq2Seq 모델 구현

LSTM Encoder와 Decoder를 이용하여 뉴스 본문으로부터 헤드라인을 생성하는 모델을 구현하였다.

Encoder는 뉴스 본문의 문맥 정보를 Hidden State와 Cell State로 표현하고, Decoder는 이를 이용하여 요약문을 순차적으로 생성하도록 구성하였다.

Attention Mechanism을 적용하여 Decoder가 각 토큰을 생성할 때 Encoder의 여러 위치에 해당하는 정보를 참고할 수 있도록 하였다.

추가로 다음과 같은 학습 안정화 방법을 적용하였다.

- Padding 위치에 대한 Attention Mask 적용
- 가변 길이 시퀀스 처리를 위한 `pack_padded_sequence()` 사용
- CrossEntropyLoss 계산 시 Padding 제외
- Gradient Clipping 적용
- Early Stopping 및 최적 Validation Loss 모델 복원

### Step 4. 실제 요약문 생성 및 비교

학습 과정에서는 Teacher Forcing을 이용하여 실제 정답 토큰을 Decoder의 입력으로 제공하였다.

추론 과정에서는 Greedy Decoding을 적용하여 모델이 생성한 토큰을 다음 단계의 입력으로 사용하도록 구성하였다.

학습된 Encoder, Decoder 및 출력층을 추론 과정에서도 그대로 사용하였으며, 실제 헤드라인과 생성된 요약문을 비교하였다.

### Step 5. Summa 기반 추출적 요약

Summa의 TextRank 알고리즘을 활용하여 뉴스 본문에서 중요도가 높은 문장을 선택하였다.

일부 짧은 뉴스 기사에서는 Summa가 요약문을 생성하지 못하는 문제가 발생하였다. 이를 보완하기 위해 첫 문장을 선택하는 Lead-1을 대체 방식으로 적용하였다.

또한 Summa 자체 요약 성공 여부를 기록하여 대체 방식이 포함된 결과와 구분하였다.

### Step 6. 추가 실험 및 성능 평가

기본 프로젝트에서 요구하는 요약문 비교에 더해 다음과 같은 분석을 진행하였다.

- ROUGE-1, ROUGE-2, ROUGE-L 정량 평가
- Lead-1 기준 모델과의 성능 비교

## 5. 문제 발생 및 해결 과정

### 5.1. 초기 모델의 UNK 반복 생성 문제

초기에는 단어의 등장 빈도를 기준으로 Vocabulary를 구축하고 Attention Seq2Seq 모델을 학습하였다.

Train Loss와 Validation Loss는 정상적으로 감소하였으나, 실제 요약문을 생성하는 과정에서 `<UNK>` 토큰이 반복적으로 출력되는 문제가 발생하였다.

처음에는 학습 데이터와 Epoch가 부족한 것이 원인이라고 생각하여 학습 데이터 규모와 학습 횟수를 증가시켰다.

그러나 일부 영어 단어가 생성되기 시작했음에도 UNK 반복 문제는 완전히 해결되지 않았다.

### 5.2. 문제 원인 분석

뉴스 기사에는 인명, 지명, 기업명 등 등장 빈도가 낮은 단어가 많이 포함되어 있다.

기존 단어 기반 토큰화 방식에서는 단어사전에 등록되지 않은 서로 다른 단어들이 모두 동일한 UNK 토큰으로 변환되었다.

이러한 UNK 토큰이 Decoder의 학습 정답에도 포함되는 구조가 반복 생성의 원인 중 하나라고 판단하였다.

또한 Greedy Decoding 과정에서 이전에 생성된 UNK가 다시 Decoder의 입력으로 사용되면서 반복 생성에 영향을 미쳤을 가능성을 검토하였다.

### 5.3. SentencePiece를 이용한 개선

이전 Day 2 프로젝트에서 학습한 SentencePiece를 이번 문제 해결에 활용하였다.

기존 Word-level 토큰화 대신 SentencePiece BPE를 적용하였으며, Byte Fallback을 사용하여 학습되지 않은 문자도 바이트 단위로 표현할 수 있도록 구성하였다.

| 항목 | 기존 방식 | 개선 방식 |
|---|---|---|
| Tokenization | Word-level | SentencePiece BPE |
| 희귀 단어 처리 | UNK 변환 | 서브워드 분리 |
| 미등록 문자 처리 | UNK 변환 가능 | Byte Fallback |
| Vocabulary | 본문과 요약문 각각 구축 | 공통 Vocabulary |
| Decoding | 단어 단위 연결 | SentencePiece Decoding |

단순히 추론 과정에서 UNK 출력을 강제로 제한하는 것이 아니라, 토큰화 방식 자체를 변경하여 문제를 개선하였다는 점에서 의미가 있었다.

## 7. 최종 요약 성능 비교

### 7.1. ROUGE 정량 평가

동일한 테스트 뉴스 기사 200건을 대상으로 추상적 요약과 추출적 요약의 성능을 비교하였다.

| Method | ROUGE-1 | ROUGE-2 | ROUGE-L | 평균 단어 수 |
|---|---:|---:|---:|---:|
| Attention + SentencePiece | 0.1368 | 0.0198 | 0.1257 | 10.68 |
| Summa + Fallback | 0.3280 | 0.1321 | 0.2734 | 24.03 |
| **Lead-1** | **0.4028** | **0.1824** | **0.3435** | 25.60 |

추상적 요약 모델은 추출적 요약보다 짧은 문장을 생성하였으나, 모든 ROUGE 지표에서 상대적으로 낮은 성능을 나타냈다.

이번 실험에서는 단순히 뉴스의 첫 문장을 선택하는 Lead-1이 가장 높은 ROUGE 점수를 기록하였다.

뉴스 기사는 중요한 정보를 앞부분에 배치하는 경우가 많으므로, 이러한 데이터의 특성이 Lead-1의 성능에 영향을 미쳤을 가능성이 있다고 판단하였다.

### 7.2. Summa 요약 성공률

| 항목 | 결과 |
|---|---:|
| 전체 평가 기사 | 200건 |
| Summa 자체 요약 성공 | 147건 |
| Lead-1 대체 적용 | 53건 |
| Summa 자체 요약 성공률 | 73.50% |

Summa가 자체적으로 요약문을 생성한 147건에 대해서도 별도로 비교하였다.

| Method | ROUGE-1 | ROUGE-2 | ROUGE-L |
|---|---:|---:|---:|
| Attention + SentencePiece | 0.1397 | 0.0232 | 0.1290 |
| Summa | 0.3136 | 0.1259 | 0.2658 |
| **Lead-1** | **0.4154** | **0.1944** | **0.3612** |

Summa가 정상적으로 요약문을 생성한 기사만을 대상으로 비교하였을 때도 Lead-1의 성능이 높게 나타났다.

따라서 이번 결과가 단순히 Summa의 요약 실패 사례에 의해서만 발생한 것은 아님을 확인하였다.

| Modi 총리의 행정 개혁 관련 발언 | 2/3 | 3/3 | 12.50% | 50.00% |
| 인도 정치인의 보상금 제안 | 1/3 | 3/3 | 0.00% | 40.00% |
| 법원의 인물 사진 사용 금지 | 2/3 | 3/3 | 25.00% | 50.00% |
| Amazon의 증강현실 기능 | 3/3 | 3/3 | 0.00% | 10.00% |
| 화산 활동과 과거 지구온난화 | 1/3 | 3/3 | 0.00% | 11.11% |

첫 번째와 두 번째 기사에서는 Summa 대신 Lead-1을 적용하였다.

추상적 요약에서는 일부 핵심 단어를 생성하는 데 성공하였으나, 원문과 관계없는 인물이나 사건이 등장하는 문제가 확인되었다. 또한 동일한 단어나 표현이 반복되는 경우도 있었다.

반면 추출적 요약은 원문에 존재하는 문장을 사용하므로 사실 보존과 문법 완성도 측면에서 상대적으로 유리하였다. 다만 선택된 문장이 항상 기사의 핵심 내용을 충분히 포함하는 것은 아니었다.

이를 통해 문법적으로 자연스러운 문장이 반드시 올바른 요약문인 것은 아니며, ROUGE와 함께 실제 내용의 정확성을 평가할 필요가 있음을 알 수 있었다.

## 8. Attention Heatmap 분석

Decoder가 요약문을 생성할 때 Encoder의 각 입력 토큰에 부여하는 Attention 가중치를 Heatmap으로 시각화하였다.

가로축에는 뉴스 본문의 서브워드 토큰을 배치하고, 세로축에는 Decoder가 생성한 서브워드 토큰을 배치하였다.

이를 통해 생성 단계에 따라 입력 토큰에 서로 다른 가중치가 부여되는 것을 확인하였다.

다만 높은 Attention 가중치가 반드시 올바른 요약문 생성의 원인이라고 판단할 수는 없다. 현재 모델에서는 사실 오류와 반복 생성 문제가 남아 있으므로 Attention 적용 여부에 따른 별도의 비교 실험이 필요하다고 생각한다.

## 10. 프로젝트 평가 및 회고

### 10.1. 학습 지표와 실제 모델 성능의 차이

이번 프로젝트에서 가장 크게 깨달은 부분은 Loss가 감소한다고 해서 모델이 반드시 원하는 결과를 생성하는 것은 아니라는 점이다.

초기 모델에서는 Train Loss와 Validation Loss가 모두 감소하였음에도 실제 요약문에서는 UNK가 반복적으로 출력되었다.

이전 감성분석 프로젝트에서는 Accuracy와 F1-score를 통해 모델 성능을 비교할 수 있었지만, 텍스트 생성 문제에서는 문법적인 완성도와 의미 전달 여부, 사실관계까지 함께 고려해야 한다는 차이가 있었다.

따라서 모델 학습 결과를 판단할 때 수치와 그래프뿐만 아니라 실제 모델의 출력 결과를 직접 확인하는 과정이 중요하다고 느꼈다.

### 10.2. 이전 학습 내용을 활용한 문제 해결

처음 UNK 반복 생성 문제가 발생하였을 때는 학습 데이터와 Epoch를 늘리는 방법을 우선적으로 생각하였다.

그러나 학습량을 증가시킨 이후에도 문제가 지속되면서 모델의 학습 조건뿐 아니라 데이터가 어떤 방식으로 표현되고 있는지 살펴볼 필요가 있다고 판단하였다.

이 과정에서 이전 프로젝트에서 학습한 SentencePiece를 적용하였으며, 실제로 입력 데이터와 생성 결과에서 UNK가 검출되지 않는 것을 확인하였다.

각 프로젝트에서 배운 기술을 새로운 문제 해결에 활용할 수 있다는 점이 인상적이었다.

### 10.3. 복잡한 모델이 항상 좋은 성능을 보장하지는 않는다

이번 실험에서는 Attention 기반 Seq2Seq나 Summa보다 단순히 뉴스의 첫 문장을 선택하는 Lead-1이 높은 ROUGE 점수를 기록하였다.

처음에는 복잡한 모델을 사용하면 더 좋은 결과를 얻을 수 있을 것으로 생각하였지만, 실제 성능은 데이터의 특성과 해결하고자 하는 문제에 따라 달라질 수 있었다.

따라서 새로운 기술을 적용하는 것 자체보다 기존의 단순한 방법과 비교하여 실제로 어떤 개선이 이루어졌는지 검증하는 과정이 중요하다고 생각한다.

### 10.4. 생성형 AI의 한계

SentencePiece를 적용한 이후에는 UNK 문제가 개선되었지만, 모델이 원문에 없는 인물이나 사건을 생성하는 문제가 남아 있었다.

이를 통해 자연스러운 문장을 생성하는 능력과 정확한 사실을 전달하는 능력이 서로 다르다는 점을 이해하였다.

특히 뉴스 요약과 같이 정확한 정보 전달이 중요한 분야에서는 생성된 문장을 원본 정보와 비교하고 검증하는 과정이 필요하다고 생각한다.

그러나 실제 뉴스의 핵심 내용을 정확하게 전달하는 수준까지는 도달하지 못하였다. 또한 여러 실험 조건을 동시에 변경하였기 때문에 각 조건이 성능에 미치는 영향을 개별적으로 분석하기에는 한계가 있었다.

향후에는 다음과 같은 방향으로 실험을 개선하고자 한다.
